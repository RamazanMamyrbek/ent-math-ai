# 1. Решение по версии программы

На дату этого документа Национальный центр тестирования уже опубликовал общий формат ЕНТ-2027: каждый профильный предмет содержит **40 заданий и оценивается максимум в 50 баллов**. При этом отдельной новой предметной спецификации математики «для использования с 2027 года» в опубликованных материалах НЦТ пока не обнаружено.

Поэтому текущий canonical curriculum основан на последней опубликованной предметной спецификации:

> **«Спецификация теста по предмету “Математика” для ЕНТ — для использования с 2026 года».**

Карта versioned. При появлении новой спецификации мы создаём новую `curriculum_version`, но не ломаем уже накопленные `skill_code`, evidence и историю ученика.

# 2. Что официально, а что является нашей декомпозицией

Официальная спецификация задаёт **10 разделов и 18 тем**. НЦТ не публикует в этой спецификации точную долю каждой отдельной темы в каждом варианте.

Поэтому:

- 10 разделов и 18 тем — **официальный уровень**;
- granular skills ниже — **внутренняя продуктовая декомпозиция**;
- `P0/P1/P2` — **приоритет производства контента**, а не официальная частота на ЕНТ;
- `A/B/C` — характеристика конкретного задания, а не целого skill;
- нельзя придумывать «вес темы на ЕНТ», если он не подтверждён официальным blueprint или накопленными калиброванными данными.

Перед массовым наполнением Question Bank эту карту должен проверить сильный преподаватель профильной математики ЕНТ.

# 3. Официальная структура теста

По официальной спецификации профильной математики:

- 40 тестовых заданий;
- 25 — выбор одного правильного ответа;
- 5 — выбор одного правильного ответа на основе одного контекста;
- 5 — выбор одного или нескольких правильных ответов;
- 5 — установление соответствия;
- средняя ориентировочная продолжительность одного задания — 2 минуты;
- трудность: `A ≈ 50%`, `B ≈ 30%`, `C ≈ 20%`.

Canonical question formats:

```text
SINGLE_CHOICE
CONTEXT_SINGLE_CHOICE
MULTI_SELECT
MATCHING
```

# 5. Правила skill IDs

`skill_code` — стабильный технический идентификатор.

Правила:

1. Не содержит год, язык и difficulty.
2. Переименование текста не меняет код.
3. Новый смысл не получает старый код.
4. Удалённый skill становится `RETIRED`.
5. Question имеет один `PRIMARY` skill и при необходимости `SECONDARY`/`PREREQUISITE` skills.

Примеры:

```text
EQ-QUAD-02
TRIG-ID-03
PLN-MET-03
CALC-DER-04
```

# 6. Product Coverage Tiers

- **P0** — фундамент и Closed Alpha;
- **P1** — расширение Alpha/Beta;
- **P2** — полное покрытие, сложные и комбинированные ветви.

Это **не официальная важность темы**.

# 9. Как Adaptive Engine использует prerequisites

Пример:

```text
Ученик дважды ошибается в EQ-TRIG-03
        ↓
EQ-TRIG-03 требует EQ-QUAD-03 + EQ-TRIG-02
        ↓
EQ-QUAD-03 mastery = 0.31
EQ-TRIG-02 mastery = 0.74
        ↓
не делаем вывод
«ученик не знает тригонометрию»
        ↓
даём targeted check по EQ-QUAD-03
        ↓
при подтверждении prerequisite gap
временно лечим квадратные уравнения
```

Это одно из главных отличий adaptive learning от простого dashboard по темам.

# 10. Difficulty Model

`A/B/C` относится к item.

## A

- стандартный алгоритм;
- прямое применение формулы;
- мало шагов;
- знакомая форма.

## B

- нужно распознать модель;
- выбрать метод;
- выполнить несколько преобразований;
- интерпретировать график/рисунок/таблицу.

## C

- несколько skills одновременно;
- сложный выбор метода;
- multi-step reasoning;
- перенос знаний в новую форму.

Один skill должен иметь items разной сложности.

# 12. Question-to-Skill Mapping Contract

Каждый approved question обязан иметь:

```yaml
curriculum_version: ENT-MATH-2026-v1
official_topic: '15'
primary_skill: PLN-MET-03
secondary_skills:
  - TRIG-VAL-01
prerequisite_skills:
  - PLN-TRI-01
difficulty: B
format: SINGLE_CHOICE
estimated_time_sec: 120
competency_tags:
  - DIAGRAM_INTERPRETATION
  - METHOD_SELECTION
```

Ограничения:

- ровно один `primary_skill`;
- обычно не более 3–4 secondary skills;
- C-level item может быть multi-skill;
- mapping должен иметь reviewer/source metadata;
- approved item не существует без answer validator.

# 13. External Assessment Mapping

Внешние результаты бывают разной granularности.

## Item-level

Если есть условие и результат отдельного задания:

```text
external item
→ official topic
→ primary skill
→ mapping confidence
→ Learning Evidence
```

## Topic-level

Например:

```text
Тригонометрия: 4/7
```

Если granular skill определить нельзя, evidence остаётся на aggregate topic node.

**Запрещено** автоматически размазывать `4/7` по всем дочерним skills.

## Total score only

Например:

```text
Математика: 29/40
```

Используется для readiness/score calibration, но не присваивает mastery конкретным skills.

# 17. Skill Mastery vs Topic Mastery

Source of truth:

```text
Skill Mastery
```

Topic mastery — derived view.

Например:

```text
TRIG-ANG-01  0.91
TRIG-VAL-01  0.82
TRIG-ID-01   0.63
TRIG-ID-02   0.41
TRIG-ID-03   0.28
        ↓
UI aggregate: «Тригонометрия»
```

Нельзя хранить только одно число `Trigonometry = 61%` и терять диагностическую глубину.

# 19. Что нельзя хранить как curriculum truth

Не кодировать навечно:

- предположительную частоту тем;
- проценты из одного пробника;
- номера заданий;
- UI order;
- Alpha tier;
- модель Gemini;
- mastery algorithm;
- текущую recommendation formula.

Curriculum — стабильный предметный слой.

# 20. Уточнение по mathematical analysis

Официальная Topic 13 сформулирована широко: «начала математического анализа» и математическое моделирование.

Внутренняя декомпозиция включает:

- функции и графики;
- производную;
- исследование функции;
- экстремумы;
- первообразную;
- определённый интеграл;
- математическое моделирование.

Это согласуется с актуальными требованиями общего среднего образования, где прямо упоминаются производная, экстремумы и определённый интеграл с формулой Ньютона–Лейбница.

Это **детализация official parent topic**, а не утверждение о фиксированном количестве таких заданий на ЕНТ.
